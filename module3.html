Rule 3Mutate → the caller sees it.
Reassign → the caller doesn't.

Now the most famous Python trap.

def add_item(item, bucket=[]):
    bucket.append(item)
    return bucket

print(add_item("apple"))
print(add_item("mango"))
Output['apple'] ['apple', 'mango'] ← where did apple come from?

The default [] is made once, when def runs.

Every call shares that same list.

def add_item(item, bucket=None):
    if bucket is None:
        bucket = []
    bucket.append(item)
    return bucket
Output['apple'] ['mango']

Who cleans it up?

Every object keeps a reference count.

2 names point here → count 2
one name leaves → count 1
count hits 0 → memory is freed immediately
a = [1, 2]
b = a
del a
print(b)
Output[1, 2] ← the object is still alive

del removes a name, not the object.

a = []
a.append(a)   # the list points at itself
del a         # count never reaches 0...

...so Python's garbage collector (gc) finds such cycles and frees them.

a = 256
b = 256
print(a is b)   # True: small ints are cached

For bigger numbers like 257, the answer can be True or False depending on how the code runs.

Never rely on it. Compare numbers and strings with ==.

The whole lesson, in five lines

  1. Variables are names, not boxes.
  2. Assignment never copies.
  3. Immutable objects never change — you get a new object.
  4. Mutate: caller sees it. Reassign: caller doesn't.
  5. Nested data needs deepcopy. Use is only for None.
