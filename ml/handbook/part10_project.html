Part 10 · Session 5 (Day 2, ~6 hours)

The project: an end-to-end tabular ML baseline

Your team builds a complete, documented ML solution on one dataset, from problem statement to a working app, using everything in Parts 1–9. You won't start from zero: you already have your problem statement, split and baseline from Session 1, models from Session 2, and an improvement from Session 3.

10.1 The brief

User story: As a business owner, I want a working, documented model that predicts [target] from [data], with a simple app, so that my team can use it and trust its limits.

Acceptance criteria (all required)

# Requirement Where it lives
1 Clear problem statement, target and metric (with a reason) README
2 Leakage-aware split (split before fitting anything; seed recorded) src/data.py, README
3 Preprocessing in a scikit-learn pipeline src/features.py
4 A baseline plus at least two candidate models, same folds src/models.py, reports/cv_results.csv
5 Appropriate metrics; test set used once reports/metrics.json
6 Brief error analysis explained in context README (confusion matrix or residuals)
7 Saved pipeline predicts on unseen rows in a fresh session; tests pass predict.py, pytest
8 Streamlit app showing a prediction and the results app.py
9 README write-up and model card completed README.md, MODEL_CARD.md
10 Code, outputs and history on GitHub your repository

Stretch (optional): a FastAPI endpoint · tuning with python train.py --tune · a clustering comparison.

10.2 The starter project

Download ml-project-starter.zip: a ready-made folder with the 5 datasets, configs, and working code for training, saving, batch prediction, input validation, a fairness report, tests and a Streamlit app. It runs out of the box with a baseline only. Your team makes the ML decisions: models, features, metric, threshold, interpretation.

# 1 · unzip, put it under Git, push to your own GitHub repository
cd ml-project-starter
git init && git add . && git commit -m "Starter project"
pip install -r requirements.txt

# 2 · choose your dataset
cp datasets/titanic/config.json config.json

# 3 · run everything
python train.py
python predict.py --input reports/new_rows_example.csv
pytest -q
streamlit run app.py

Then search the code for TODO (the starter's README lists them by session).

10.4 The 6 hours, step by step

Time Step You produce TA checkpoint
0:00–0:30 Set up: unzip, Git, GitHub, config, first train.py run repo online; baseline scores "Show me your repo and baseline."
0:30–1:30 Data & problem: inspect, clean in src/data.py if needed, write the problem statement README sections 1–3 "Why this metric? Why this split? Which column worried you for leakage?"
1:30–2:30 Models: add ≥ 2 candidates; compare with CV reports/cv_results.csv "Are all models compared on the same folds? Which won, and by how much vs the spread?"
2:30–3:30 Improve: one feature hypothesis and/or tuning; record each try experiments.csv, README section 5 "What was your hypothesis, and did the data support it?"
3:30–4:15 Evaluate & explain: test once; error analysis; fairness table reports/, README "Explain one false positive and one false negative in business terms."
4:15–5:00 Product: predict.py on new rows, pytest, app improvements working app "Load your model in a fresh terminal and predict."
5:00–5:30 Document: model card, README, final commit MODEL_CARD.md "What should this model NOT be used for?"
5:30–6:00 Demo: 5 minutes per team live demo rubric scoring

10.5 The demo (5 minutes)

  1. The problem in one sentence and the decision it supports (30 s)
  2. The data and one surprising finding (45 s)
  3. Models compared and why you chose the winner (60 s)
  4. Live app: one prediction, explained (60 s)
  5. Limits and risks: from your model card (45 s)
  6. One thing you would do next (30 s)

10.6 Rubric

Area Weight Excellent looks like
Problem framing and data handling 20% clear decision; cleaning choices explained with reasons; leakage checked
Pipeline and reproducibility 20% everything in a pipeline; seed recorded; experiments.csv used; tests pass
Evaluation and error analysis 20% fair CV comparison against the baseline; right metric; errors explained in business terms
App integration and usability 15% app loads the saved model, validates input, explains the result
Code and documentation 10% clean commits; README a stranger can follow
Responsible-use discussion and demo 15% honest model card: limits, fairness, privacy, monitoring; clear demo

10.7 Common problems and fixes

Symptom Likely cause Fix
KeyError: 'column' config target/drop names don't match the CSV check spelling and case in config.json
Score suspiciously close to perfect leakage (an ID-like or after-the-fact column) look at the top features; drop the culprit
Classification recall 0 baseline only, or threshold too high add models; choose a threshold
predict.py rejects input missing column or text in a number column read the ERROR lines; fix the file
Model won't load elsewhere different scikit-learn version install the version in reports/metrics.json
App says "No trained model found" train.py not run in this folder run python train.py first
