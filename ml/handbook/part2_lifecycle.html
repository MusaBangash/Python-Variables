Part 2 · Session 1

The ML project lifecycle: from data collection to deployment

A model is a small part of a real ML project. Most of the work happens before training (getting and preparing data) and after training (deploying, watching and fixing). This part gives you the full map. Part 3 then zooms in on the steps you will code yourself.

Think of opening a restaurant. Cooking (training the model) is one step. Before it you choose the menu (the problem), buy and wash ingredients (collect and clean data). After it you serve customers (deployment), listen to complaints and fix recipes (monitoring). A great cook with rotten ingredients still serves bad food.

2.1 The 12 stages at a glance

# Stage Key question Typical tools
1 Define the problem What decision will the prediction improve? How do we measure success? meetings, a one-page problem statement
2 Collect data Where does the data come from, and do we have the answers (labels)? SQL, CSV/Excel, APIs, logs, surveys, public datasets
3 Store and access data Where does it live, and can we load it reliably again? files, databases, data warehouses
4 Explore (EDA) What does the data look like? What patterns and problems are there? pandas, matplotlib, seaborn
5 Clean data Missing values, duplicates, wrong types, impossible values? pandas
6 Split data Which rows train the model, which rows test it? scikit-learn train_test_split
7 Prepare features How do we turn raw columns into numbers a model understands? scikit-learn Pipeline, ColumnTransformer
8 Choose and train models Which models fit this problem? scikit-learn, XGBoost
9 Evaluate and improve Is it better than the baseline? Where does it fail? Can we tune it? metrics, cross-validation, GridSearchCV
10 Final test How will it perform on truly new data? the locked test set, used once
11 Deploy How do people or systems get predictions? joblib, Streamlit, FastAPI, cloud
12 Monitor and maintain Is it still working next month? When do we retrain? logs, dashboards, drift checks

It is a loop, not a straight line: monitoring often sends you back to collecting more data or adding a feature.

In real projects, roughly 60–80% of the time goes into stages 2–7 (data). Beginners expect to spend most time choosing models; professionals spend most time on data.

2.2 Stage by stage

Stage 1 · Define the problem

Write one sentence: We want to predict [target] for [each row] using [information available at the moment of prediction], so that [someone] can [decide something]. Success = [metric], and we must beat [a simple baseline].

Also decide: is it regression (a number) or classification (a category)? Is a simple rule good enough? What does a mistake cost?

Starting with the data or the model instead of the decision. If you can't name who will use the prediction and what they will do differently, stop: there is no project yet.

Stage 2 · Collect data

Source Example Watch out for
Company databases customer records, sales, transactions (queried with SQL) access permissions; personal data
Files CSV, Excel exports different versions; manual edits
APIs weather, exchange rates, social media rate limits; changes in format
Logs and sensors website clicks, machine temperatures huge volume; gaps when a sensor fails
Surveys and forms customer feedback biased answers (only some people reply)
Public datasets Kaggle, UCI, government data may not match your real situation
Labelling people tag examples (spam / not spam) expensive, slow, labellers disagree

Two questions decide everything: 1. Do we have labels (the answers)? If yes → supervised learning is possible. If no → unsupervised, or collect labels first. 2. Is the data representative? Does it look like the situations where the model will be used? (Part 1: non-representative data and sampling bias.)

Collecting personal data without permission, or keeping it insecurely. Collect only what you need, protect it, and follow the law (Part 9).

Stage 3 · Store and access data

For learning, a CSV file is enough. In companies, data lives in databases (tables queried with SQL) or data warehouses (large, organised stores for analysis). What matters for ML: you must be able to load exactly the same data again later (reproducibility), and know when each value was recorded (to avoid using future information).

Stage 4 · Explore the data (EDA = exploratory data analysis)

Look before you model: sizes, types, distributions, relationships, surprises. Charts are your main tool (Part 3, step 5). The goal is to understand and to spot problems, not to make pretty pictures.

Stage 5 · Clean the data

Fix or remove: missing values, duplicates, wrong data types (numbers stored as text), impossible values (age 250), inconsistent categories ("Male", "male", "M"). Always ask why something is wrong before fixing it.

Stage 6 · Split the data

Separate a test set before any modelling, and lock it away. This is how we get an honest estimate of performance on new data (Part 1, 1.9).

Stage 7 · Prepare features (preprocessing and feature engineering)

Models need numbers with no blanks. We fill missing values, encode categories as numbers, scale numeric columns, and create useful new columns. We put all of this in a pipeline so it is applied identically to training data, test data and future data.

Stage 8 · Choose and train models

Start with a baseline (the simplest possible guess), then a simple model (linear or logistic regression), then stronger ones (trees, forests, boosting). Training = the model learns its parameters from the training data.

Stage 9 · Evaluate and improve

Measure with the right metric, compare models fairly with cross-validation, study the mistakes, add features, tune settings. Repeat.

Stage 10 · Final test

Open the test set once, for the chosen model only. This number is what you report.

Stage 11 · Deploy

Way How it works Example
Batch run the model on a file of rows every night/week a call list of risky customers every Monday
Real-time API another program sends one row, gets a prediction in milliseconds a loan app checking risk while the customer waits
App / dashboard a person types inputs into a form a Streamlit page for the sales team
Embedded the model runs inside a phone or device keyboard word suggestions

To deploy, we save the whole pipeline (preprocessing + model) to a file with joblib, and load it wherever predictions are needed.

Stage 12 · Monitor and maintain

The world changes; models silently get worse. Watch: - Data drift: new inputs look different from training data (e.g. many more new customers). - Performance drift: accuracy drops when real outcomes arrive. - Errors and complaints: wrong inputs, crashes, unfair results.

Then retrain with fresh data, with the same pipeline and the same tests.

2.3 Who does what in a company

Role Main work
Business owner / product manager defines the problem, decision and success
Data engineer collects, stores and delivers reliable data
Data scientist explores data, builds and evaluates models
ML engineer deploys, scales and monitors models
Domain expert explains what the data means (doctors, sales staff)

In a small team, you are all of them. That's what the project on Day 2 practises.

Check yourself

1. Which stage usually takes the most time?The data stages (collecting, exploring, cleaning, preparing): often 60–80% of the work.
2. Why must we split the data before preparing features?So that nothing learned from the test rows (means, categories, choices) leaks into training. The test set must stay "new".
3. Name two ways to deploy a model.Batch (score a file regularly), real-time API, an app such as Streamlit, or embedded in a device.
4. What is data drift?When new input data starts to look different from the training data, so the model's performance may drop.
5. You have customer data but no record of who left. What can you do?Unsupervised learning (e.g. segments), or start collecting labels (record who leaves) so supervised learning becomes possible later.
