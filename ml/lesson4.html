How a model actually learns

Gradient descent: the engine inside every model, from churn to ChatGPT.

Press N for presenter lines · F fullscreen · arrows to move

Start with the simplest model: a straight line

prediction = θ₀ + θ₁ × months

θ₀ (intercept)

where the line starts

θ₁ (weight)

how steeply it rises: $76.3 per month

Why? These numbers are the model's parameters. Training = finding the parameter values that make the error as small as possible. A neural network is the same idea with billions of parameters.

First, define "error": mean squared error

error = average of (prediction − truth)²
1 Squaring makes every miss positive, so misses can't cancel out
2 Big misses count much more: 10 off costs 100, 2 off costs 4
3 It is smooth: it has a slope everywhere, so we can walk downhill on it

Two ways to find the best line

MethodHow it worksGood atBad at
Closed-form (normal equation / SVD)solve the maths in one shotsmall linear problems: instant, exactcost explodes with many features; only works for linear models
Gradient descentstart anywhere, step downhill, repeathuge data, any model with a slope (neural nets, LLMs)needs a learning rate; slower on small problems
Best choice: small linear problems → let the library solve it exactly (scikit-learn uses an SVD-based solver). Anything big or non-linear → gradient descent. Check: our hand-written gradient descent found weight 0.8262, exactly what the one-shot solution gives.

Gradient descent in one picture

Lost on a foggy mountain? Feel the slope, step downhill.

Why? You can't see the valley. But you can feel which way the ground tilts under your feet. Step the other way. Repeat until the ground is flat: you're at the bottom.
new weight = old weight − learning rate × slope

Slope (gradient)

which way the error goes up, and how steeply; computed from the data

Learning rate

how big each step is; you choose it (a hyperparameter)

The step size decides everything

Same model, four step sizes

Why? Too small (0.01): after 60 steps still far from the bottom. Right (0.1): done in a few steps. Too big (1.05): error explodes to over 50,000.

Choosing the learning rate: all the options

OptionHowWhen
Library defaulttrust the solver's built-in choicescikit-learn linear/logistic models: they pick it for you

Best choice: start from the default, search on a log scale if you train by hand, and use Adam with a schedule for neural nets.

Why we always scale features first

Why? Raw months (0–72) and bills (18–119) stretch the bowl into a long narrow valley, so steps zig-zag across it and must stay tiny. Scaled to the same range, the bowl is round and the path goes straight down: 53,586 steps became 16.

How much data per step? Three variants

VariantData per stepSteps in 20 passesCharacter
Batchall 5,634 customers20accurate steps, but few and slow on big data
Stochastic (SGD)1 customer112,680very noisy steps; cheap each
Mini-batch32 customers3,540the balance: fairly smooth, fast, GPU-friendly
Best choice: mini-batch. It is what every deep-learning framework does: batches of 32–512 fit GPU memory, give fairly stable steps, and many updates per pass. Our from-scratch mini-batch model reached test AUC 0.840 vs 0.841 for the library's exact solver.
Why? Bonus fact: for linear and logistic regression the error bowl has one single bottom (it is "convex"), so any sensible method finds the same answer. Neural networks have bumpy landscapes with many valleys, yet mini-batch gradient descent still works remarkably well in practice.

Part C · when a straight line is too simple

Let the line bend: polynomial features

Why? Add new columns like months², months × bill. The model stays "linear in its weights", so the same training works, but it can now draw curves. The danger: 30 features become 495, and with little data it memorises.
RegularizationAdd a penalty for large weights to the error.
The model must earn every big number.

Experiment: 300 customers, 495 features

Why? With no penalty it scores a perfect 1.0 on its 300 customers and only 0.715 on unseen ones: memorising. Raising the penalty lifts unseen quality to 0.784. Push it too far and it becomes too simple again.

All the regularization options

OptionPenalty / ideaSpecial effectUse when
Ridge (L2)sum of squared weightsshrinks all weights smoothlydefault choice; many useful features

Best choice: Ridge by default; Lasso when you want fewer features; Elastic Net when features overlap; early stopping for boosting and neural nets. Always pick the strength with cross-validation.

Lasso picks features for you

Why? From 29 features to 7, quality drops only from 0.842 to 0.829. A model with 7 inputs is far easier to explain, monitor and keep running.

Part D · from numbers to yes / no

Logistic regression: a line, then a squash

Its error: log loss

Says 90% leave · they leave

small penalty (0.11)

Says 1% leave · they leave

huge penalty (4.6)

Why? Log loss punishes confident wrong answers hardest. Why not squared error? Combined with the sigmoid, squared error makes a bumpy surface with flat spots; log loss keeps a single smooth bowl, so gradient descent reliably finds the bottom.

More than two answers: softmax

Why? Softmax turns any list of scores into probabilities that add up to 100%. Bigger score, bigger share. Example: the next word after "The capital of France is".

The bridge to modern AI

How ChatGPT and Claude learned, in this lesson's words

1 Pick the next word with softmax over ~100,000 tokens
2 Measure the error with log loss (called cross-entropy)
3 Improve with mini-batch gradient descent, billions of times

Check yourself · 1 of 5

Training loss suddenly shoots up to huge numbers. First suspect?

AnswerA learning rate that is too large: steps overshoot the bottom and grow each time. Lower it (e.g. ÷10).

Check yourself · 2 of 5

Gradient descent takes forever on raw features. Why, and the fix?

AnswerDifferent feature ranges stretch the error bowl into a narrow valley; steps zig-zag. Scale the features.

Check yourself · 3 of 5

Why do deep-learning frameworks train with mini-batches?

AnswerStable enough steps, many updates per pass, and batches fit GPU memory.

Check yourself · 4 of 5

Ridge or Lasso if your manager wants a model with very few inputs?

AnswerLasso: it sets weak weights to exactly zero, selecting features.

What do logistic regression and ChatGPT have in common?

AnswerBoth turn scores into probabilities (sigmoid / softmax) and are trained by gradient descent on log loss.
